# 产品计划 · 世界巡演(World Tour)

在真实世界的十个地标里施放法术,顶部下拉切换场景。

> **状态:已实现。** 见 `src/config/scenes.js`、`src/ui/SceneSelector.js`。
> 打开 `?streetview` 即可,或直接指定场景:`?streetview=machu-picchu`。

## 为什么

街景背景已经跑通:官方影像铺满全帧、地面与街面对齐、WASD 可以沿街行走。但目前只有一个写死的起点(纽约时代广场),换地方要改 URL 参数。

这份计划把它变成一个**可选择的产品**:十个国家、十个地标,每个都有走得动的路径和一句能立住的场景描述,手机上点顶部标题栏就能换。

2. `getLinks()` ≥ 2 —— 有导航链接才走得动,独立全景走不了

## 二、顶部场景选择器

### 位置与形态

手机屏幕**顶部正中**,一条可点击的标题栏。收起时只显示当前场景;点击展开下拉列表。

```
        ┌──────────────────────────┐
        │  🇺🇸  时代广场      ▾   │   ← 收起
        └──────────────────────────┘

        ┌──────────────────────────┐
        │  🇺🇸  时代广场      ▴   │   ← 展开
        ├──────────────────────────┤
        │  🇯🇵  涩谷十字路口        │
        │  🇫🇷  埃菲尔铁塔          │
        │  🇬🇷  雅典卫城            │
        │  🇷🇺  红场               │   ← 可滚动
        │  🇮🇳  泰姬陵             │
        │  ⋮                      │
        └──────────────────────────┘
```

### 规格

| 项 | 值 | 理由 |
|---|---|---|
| 位置 | `top: 10px`,水平居中 | 顶部正中是唯一两侧都不冲突的位置——右侧是技能条,底部是麦克风 |
| 收起高度 | 40px | 与右侧技能条表头(42px)视觉对齐 |
| 行高 | **48px** | 拇指点击的下限是 44px,古迹名较长需要余量 |
| 最大高度 | `min(60vh, 480px)` | 十行放不下小屏,必须可滚动 |
| 透明度 | 收起 0.6 / 展开 0.95 | 与技能条同一套逻辑:静止时让位给画面,操作时立刻可读 |
| 展开触发 | `click` | 不是 hover——手机没有 hover |
| 收起触发 | 选中一项 / 点击列表外 / `Esc` | 三条都要,缺一会困住用户 |

### 与现有 UI 的冲突

**必须处理**:顶部正中已经被 `.hud__toast`(法术选中提示)占用。方案是把 toast 下移到选择器之下,而不是让两者叠在一起。

技能条已经做过同样的避让(`@media (max-width: 760px)` 里把 toast 的 `right` 收到 152px),这次是纵向的同类问题。

### 交互流程

```
点击标题栏
   └─> 展开列表(0.22s ease)
        └─> 点选一项
             ├─> 立刻收起 + 标题更新为新场景
             ├─> 顶部出现细进度条(街景加载是网络操作,可能几秒)
             ├─> app.streetView.moveTo(lat, lng)
             │     ├─ 成功 ─> 淡入新场景 + 底部浮出场景描述(4 秒后淡出)
             │     └─ 失败 ─> 标题回退到原场景 + 提示"该地点暂时无法加载"
             └─> 清空当前战场(法术、木桩位置重置)
```

**为什么要清空战场**:换地点等于换了世界,飞在半空的法术和站在旧街道上的木桩没有理由跟着过来。

## 三、实现要点

### 数据

场景表放进 `src/config/scenes.js`,与 `settings.js` 分开——它是**内容**不是配置,会随时增删,不该和渲染参数混在一起。

```js
export const SCENES = [
  { id:'times-square', cc:'US', flag:'🇺🇸', zh:'时代广场', en:'Times Square',
    lat:40.756978, lng:-73.985881, blurb:'广告牌的峡谷。…' },
  …
];
```

### 复用已有能力

不需要新写街景逻辑,`StreetViewBackdrop` 已经有:

- `moveTo(lat, lng, radius)` —— 走 `StreetViewService` + `OUTDOOR`,已实现
- 载入后的**自愈**——落到独立全景时自动重新解析到可行走覆盖,已实现
- `walkable` 标志 —— 可以直接驱动 UI 上的"此处可行走"指示

### 需要新增

| 文件 | 内容 |
|---|---|
| `src/config/scenes.js` | 十个场景的数据 |
| `src/ui/SceneSelector.js` | 顶部下拉组件,纯 DOM,与 `VoiceHUD` 同风格 |
| `src/ui/styles.css` | 选择器样式 + toast 下移避让 |
| `src/core/App.js` | 接线:选中 → `moveTo` → 清场 → 显示描述 |

### 风险与代价

⚠️ **每次切换都是一次 Street View 计费请求。** 十个场景意味着用户可能连点十次。建议:切换加 800ms 防抖,并在 `README` 里写明这是计费操作。

⚠️ **偏远地标的加载明显更慢。** 马丘比丘和桌山的瓦片来自更远的边缘节点,实测比时代广场慢。进度条不是装饰,是必需品。

⚠️ **坐标会过期。** Google 会重新拍摄并淘汰旧全景,今天验证通过的点位一两年后可能失效。`moveTo` 的自愈能兜住小范围漂移,但**不能兜住整片覆盖被撤下**。建议把这份验证脚本留在 `self-created/` 里,定期重跑。

### 不做什么

- **不做地图选点。** 在地图上任意点击选位置意味着大量落到无覆盖或独立全景的点,体验是随机的失败。策展好的十个,比无限的不确定强。
- **不做场景收藏/自定义。** 第一版验证的是"换地方好不好玩",不是"能不能管理地点"。
- **不为每个场景调专属美术参数。** 光照、雾、地面色目前是一套通用值。真要一地一调,得先确认这个功能值得那个工作量。

## 四、验收标准

1. 十个场景**全部**能加载出官方影像(`© Google`)并且 `links ≥ 2`
2. 每个场景里按住 W 走 30 秒,**至少跨越两个全景点**
3. 手机竖屏(390×844)下:标题栏不与技能条重叠,展开后列表可滚动到第十项
4. 切换失败时有明确提示,且能退回上一个可用场景
5. 切换后战场清空,不残留上一个地点的法术

## 附:验证方法

坐标不是查来的,是用项目自己的 key 跑出来的:

```js
const { data } = await service.getPanorama({
  location: { lat, lng },
  radius: 120,
  source: google.maps.StreetViewSource.OUTDOOR   // 关键:不加这个会拿到用户全景
});
panorama.setPano(data.location.pano);
// 等 pano_changed,再读 getLinks().length 和实际落点
```

三项都要看:**链接数**(能不能走)、**版权**(是不是官方)、**偏移**(是不是还在原地)。少看一项就会把走不动的点位当成可用的——这次十八个候选里有七个是这样被筛掉的。
