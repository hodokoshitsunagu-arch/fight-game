# 文化战役运行时

## 内容边界

`src/campaign/cityChapters.js` 是发布内容的唯一入口。章节包含来源目录、传说审核状态、
八个锚点和互动定义。语言题与当地表达已从发布内容移除，第 4 点改为地点史实线索
解谜。全景 ID 不进入长期内容；锚点只保存坐标、允许
漂移半径、转场类型和在线核验状态。

每条锚点史实通过自己的 `sourceRefs` 引用章节来源目录。HUD 只渲染当前锚点解析成功的
引用，不使用章节级默认来源；缺失引用、不存在的引用，以及缺少机构、标题、HTTPS 链接
或最后核验日期的来源都会使免费内容清单校验失败。

未完成文化审核的宗教、原住民或当地传说不会成为敌人。运行时统一使用“无定形的记忆
噪声”这一抽象异常体；
战斗含义是净化遗物造成的扭曲，而不是击败真实传统。

## 状态流

```text
INTRO → NAVIGATING → INTERACTING 或 COMBAT → RESOLVING
                          ↑                      │
                          └──── 下一锚点 ────────┘
章末：RESOLVING → CROSSING → NAVIGATING
终章：RESOLVING → DONE
```

互动注册表负责 `collect`、`dialogue`、`quiz`、`puzzle`、`combat` 和
`boss` 的判定。导演只负责顺序、分支记录、失败阶梯和跨点转场。

战斗是轻量阻碍而非主要推进方式：每个街景同时最多 2 只怪物；战斗锚点在清场或安全
跳过后都会进入地点线索谜题，完成谜题才进入下一锚点。主流程因此由观察、对话、
史实判断与环境谜题驱动。

## 街景回退

`moveToAnchor()` 对 `walk` 段先依据当前 Street View 链接和目标方位逐步行走；方向
偏差、无链接或超时后只做一次户外坐标解析。仍失败时返回结构化原因，导演继续显示
互动，保证第三方地图故障不会锁住剧情。

移动开始前，统一 HUD 明确显示“当前锚点 → 目标锚点”、尝试沿链接步行或淡出转场，
并预告抵达后的互动类型和具体任务。抵达后路线结果与任务面板再次确认状态，避免玩家
只看到背景变化却不知道为什么移动、接下来要做什么。

非战斗阶段，WebGL canvas 不接收指针事件，Google 官方 viewer 的方向链接与
click-to-go 可直接操作；进入战斗时恢复 canvas 点击以施法。答题面板只让背景达到
70% 透明，文字和按钮保持不透明。

运行时回退不是路线验收。发布前用 `self-created/verify-city-chapters.mjs --live` 检查
80 个锚点的解析、漂移、户外来源和相邻链接；失败段保持淡出转场。

## 存档

v2 使用 `relic.campaign.v2.progress`：

```js
{
  version: 2,
  chapterId,
  anchorId,
  completedChapters,
  choices,
  mastery,
  hintsUsed,
  relicFragments
}
```

首次读取 v2 时，如只有旧的 `relic.campaign.progress`，按旧节点所属场景映射到对应
城市，并从该城市第一个新锚点开始；之前城市标记完成，旧碎片数保留为累计记录。
存储不可用或数据损坏时回到确定性的第一章第一点。淘汰的当前章节 ID 同样回到第一章
第一点，但保留仍可规范化的计数、完成记录和选择；淘汰的当前锚点 ID 回到该章第一点；
完成列表中的未知 ID 和未知章节选择会被
丢弃。选择锚点失效时回到该章现有的第一个对话点，选择 ID 失效时丢弃该条选择，且
`effect` 始终从当前发布内容重新派生。规范化结果会重新创建嵌套选择对象，不与解析输入
共享可变引用。
